### 行事历深度解读与隐性规律说明

上述排期表并不仅仅是任务的简单罗列，其背后隐含了多套保证项目平稳落地的工程管理机制：

1. **三步走 MVP 敏捷迭代策略 (v0.1 -> v0.2 -> v0.3)**
   * **v0.1 **：打地基。跑通底层权限、字典、基础用户逻辑，确保系统“能转起来”。
   * **v0.2 **：核心业务。攻坚最复杂的行为、活动和审批流，是项目的工作量高峰期。
   * **v0.3 **：外围与体验完善。素材、消息、评分等附加功能，同时也是为了丰富演示效果。
   * **节奏**：开发与测试呈阶梯式交替前行。

2. **API 契约前置与并行开发**
   * **API契约逻辑**：从第3周开始，开发都不再“串行”的（即等后端写完接口前端才做）。利用 API 文档和 Mock 数据，前端界面开发和后端逻辑开发解耦，缩短了阻塞等待时间。

3. **双重反馈与持续集成环**
   * **测试+产品双轨**：从第5周起，“根据测试反馈修复”和“根据产品反馈调整”，包含了测试和产品对实现的还原度审核，避免功能做偏。

4. **关键里程碑的“急刹”机制 (第4周与第7周复盘)**
   * **第4周复盘**：此时地基已打完，代码量初具规模。此处的 Review 和复盘是为了防止初期的烂代码或错误习惯蔓延到后续庞大的 v0.2 阶段中。
   * **第7周复盘**：冲刺前的最后检查。这个时候不仅查代码，更要核对“真实测试数据”和“部署环境”，确保最后的系统联调不是在虚假数据下做无用功。

5. **沙漏缓冲 (第8-9周)**
   * 项目越往后，不可控风险越大（如浏览器，小程序兼容性、性能、部署环境问题）。第8周切入“真实数据系统测试”，主动暴露深度问题；而第9周作为纯粹的缓冲周（兜底时间），缓解团队在上线前（第10周演示）的风险。
